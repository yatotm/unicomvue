# UI 设计规范

本文件是前端视觉的唯一契约。所有 `.vue` 文件必须只使用这里定义的 token、类名配方与交互规则；不在本文件中的颜色、圆角、字号、粗细、阴影一律不得出现。`tests/uiContract.test.js` 逐条把这些规则钉成断言，改了实现就得先改断言，反过来不行。

风格基准：**方向四「暖纸 · 陶土」**。暖中性的纸面（参照 Claude 的产品表面：暖白画布、更暖的纸色面板、近黑的暖墨），一支陶土色/珊瑚色的强调色负责品牌与控件；**内容的强调色不受这支色限制**，它有自己一套验证过的有序色阶与分类色板。

七条贯穿全文的原则：

0. **一个图形只有一个出处。** 反复出现的 markup 做成组件，只有 class 串重复的做成 `src/utils/ui.js` 里的配方，call site 原样引用。「你现在改的太乱了，每个地方都是单独打补丁」是被明确点名的——本轮的答案不是又一次微调，而是把同一件事的所有写法收敛成一份定义，并由契约测试盯死「别处不许再手写第二份」（§10）。
1. **圆角只有 8 / 6 / 4。** 页面卡片 8px，控件 6px，chip 与小色块 4px。除了真正的圆形标记（点图的点、头像、加载圈）用 `rounded-dot`，没有第五种圆角。「圆角弧度太大」是被明确否掉过的。**卡片内部的区域没有圆角**——它们不是卡片（§0.5）。
2. **字号只有五级：12 / 14 / 17 / 22 / 34，没有重复值。** 34px 是每屏唯一的主数字，只有看板概览的第一格能用。
3. **粗细只有两档：400 / 600，而 600 几乎不花。** 见 §3.1。「加粗的字体太多了，一眼看过去很密集，抓不住重点」是被明确点名的。
4. **文字颜色是一个闭集：三档中性墨 ＋ 七种角色墨。** 见 §2.6。「同一个页面有这么多种不同的字体、粗细、深黑浅灰」是被明确点名的。
5. **每个事实只出现一次。** 同一个数字不重复印两遍；只有一条 lane 时卡头不再重复「合计」。
6. **颜色承担分组和状态，描边不承担。** 侧边强调条被否掉过两次，永远不要再出现。
7. **卡片内部没有嵌套卡片。** 区域不带底色、不带描边、不带阴影，分界只有三种：卡片自己的全宽线、接缝网格的 1px 缝、区域内部被内边距缩进的行线（§0.5）。

## 0. 应用骨架与路由

### 0.1 两段式外壳：侧栏和顶栏是同一块壳的两面

```
┌──────────────┬─────────────────────────────────────────┐
│ 侧栏 264px   │ 顶栏：同一层纸色，薄一档（只有三个控件） │  ← 都不滚动
│ 半透明纸色   ├─────────────────────────────────────────┤
│ 铺在有渐变   │            ↕ 24px（lg:pt-6）            │
│ 的画布上     │ ╭─────────────────────────────────────╮ │
│              │ │ 主区 .main-scroll（overscroll:      │ │  ← 只有这里滚
│ 右侧一条     │ │ contain）里的那一张页面卡片         │ │
│ 通到底的     │ │  ╭───────────╮ ╭──────────────────╮ │ │
│ 发丝线       │ │  │ 嵌套区域  │ │ 嵌套区域         │ │ │
│              │ │  ╰───────────╯ ╰──────────────────╯ │ │
│ 隐私声明     │ ╰─────────────────────────────────────╯ │
└──────────────┴─────────────────────────────────────────┘
                       ↑ lg: 以下侧栏收起，底部出现标签栏
```

**顶栏不印页面标题。** 「看板 / 套餐余量总览」这一块被删掉了：那两行字每进一次页面就要被读一次，而左边的侧栏已经用高亮标出了你在哪一页。删掉它不等于这一页没有名字——

- `document.title` 仍然按路由更新（`看板 · 联通套餐余量面板`），标签页和读屏器的「页面名」由它负责；
- 主区里有一个 `class="sr-only"` 的 `<h1>{{ pageTitle }}`，标题大纲和读屏器的一级标题由它负责。

契约测试同时钉死这三件事：顶栏里没有一级标题、也没有喂给它的 prop；`AppLayout` 里有那个 sr-only 的一级标题；`router.afterEach` 仍然在写 `document.title`。

- **侧栏 `w-66`（264px）**。216px 被判「太窄」。`lg:` 以上常驻，以下整条隐藏；没有图标轨形态——四个目的地在手机上由底部标签栏承担。
- **外壳是一层纸色的 veil，有两个厚度：侧栏 50%，顶栏 30%。** 五件事一起做出这块区域：
  1. `.app-rail` 用 `--ui-rail`、`.app-header` 用 `--ui-topbar`，**两者是同一个 rgb 三元组，只有 alpha 不同**（契约直接比对这两个值），都铺在**带渐变的画布**上；
  2. 画布本身不是一块死色（`.app-shell` 的两道极柔的径向 wash），所以那两层半透明真的在采样它背后的东西——这就是 frosted 的效果来源，两块的颜色都沿着自己的长度在变；
  3. 侧栏右侧 `border-r border-divider` 一条通到底的发丝线；两块共用一道 `--ui-shell-sheen` 的内高光，沿外壳的**外沿**走（光来自左上：侧栏接住左边和上边，顶栏接住上边），所以顶边是同一条线，接缝在 x=264 处不会断；
  4. 它们**永远不动**——滚动条归主区所有（见下）；
  5. **谁厚谁薄不是随手定的**：侧栏承载文字（产品名、四个导航项、隐私声明），所以它必须厚到让墨在它两端都过 AA；顶栏承载控件，控件要比它高一档纸色（`bg-surface-raised`，和侧栏当前导航项同一个 token），所以它必须薄到留出那 1.20×。两条约束把厚度顺序钉死了。
- **顶栏以前没有自己的面**，屏幕最上面那一条 1016×56 就是整片裸画布——「顶栏没有背景」和「画布太深」其实是同一处最扎眼的地方。现在它有 veil 了，同一条 DOM 走查在改前会点名 `HEADER.app-header`（1016×56，ground=画布），改后一个都不剩。
- **仍然不给侧栏 `backdrop-filter`，顶栏的那一个必须拿得出像素证据。** 见 §16.1。契约测试里全项目只有顶栏允许出现 `backdrop-filter`。
- 主区外层挂 `@container`，分栏用容器查询（`@[60rem]` / `@[48rem]`），不用视口断点。侧栏占掉 264px 之后视口断点会算错。
- 顶栏 `sticky top-0`。`lg:` 以下它在文档滚动里，滚动时**在自己的 veil 之上**再盖一层逐渐不透明的画布色并画出发丝线（`useHeaderScrollSurface`，`background-image` 是那一层，`background-color` 永远是 veil）；`lg:` 以上它在滚动容器**外面**，进度恒为 0，于是它就是一块纯粹的半透明外壳面。主区 `pt-4 lg:pt-6`：顶栏那一行控件和卡片之间必须留出这道缝（「距离上面的刷新、截图、账号那一行太近了」）。
- **顶栏上不写字。** 它本来就不印页面标题（见上），现在这条被钉成断言：下拉面板以外的那段模板里不许出现任何墨色类，三个控件的颜色只能来自各自自带表面的 class 常量。理由有两条，都得说清：结构上，顶栏是外壳不是文字表面；数值上，30% 的 veil 在它最暗的一端给 12px 墨 4.67:1，静止刚过 AA，但一落进 hover 覆盖层就掉到 4.15:1——所以「可 hover 的小字」在这块面上是不成立的。

### 0.1.1 滚动归属：一个断点只有一个滚动主人，也只有它能回弹

「主区滚到头，整页回弹把侧栏也带着动」被修过一轮，结果修反了：侧栏和顶栏会回弹，主区反而是硬的。根因**不是**某个 `overscroll-behavior` 值写错了，而是这件事从来没有被当成一条规则来写。现在它是：

| 角色 | 谁 | `overflow` | `overscroll-behavior` | 为什么 |
| --- | --- | --- | --- | --- |
| 内容主人 | `lg:` 以上是 `main.main-scroll`；以下是文档 | `lg:overflow-y-auto` | `contain` | 链条断在它身上，回弹留给它自己 |
| 外壳 | 侧栏（含它里面那条导航列表）、顶栏、标签栏 | 列表 `overflow-y-auto` | `none` | 它们永远不动，连自己的回弹也不要 |
| 覆盖层 | 下拉面板、两个对话框的正文 | `overflow-y-auto` | `contain` | 打开时它就是自己的主人，滚动不许漏到背后的页面 |
| 区域内部的面板 | `.pane-scroll` | `overflow-y-auto` | **什么都不写** | 滚到头必须把滚动交还给主人 |

外加两条只在 `lg:` 以上成立的规则（`base.css` 末尾的 `@media (min-width: 64rem)`）：

```css
:root, body { overscroll-behavior: none; }        /* 文档不是滚动的那一个 → 它连回弹的资格都没有 */
.app-shell  { height: 100dvh; overflow: hidden; overflow: clip; }
```

三个关键点，每一个都是量出来的：

1. **「没有可滚的余量」并不能阻止 macOS 的橡皮筋。** 视口该回弹照样回弹，而回弹的是整份文档，也就是侧栏和顶栏。唯一的开关是根元素上的 `overscroll-behavior`（它会传播到视口），所以这条规则必须写在 `:root` 上，而不是写在某个盒子上。
2. **`contain` 和 `none` 的区别正是「留不留自己的回弹」。** 主区要的是 `contain`：链条断在它身上，但它自己该弹还是要弹——回弹归内容，这就是需求原话。外壳要的是 `none`：它连自己都不许动。
3. **外壳用 `clip` 而不是 `hidden`。** `hidden` 会把外壳变成一个滚动容器；浏览器实测它自己能被程序滚 23px（sticky 顶栏在这种容器里会撑出一段滚动余量），一次 `focus()` 就能把整个外壳连同侧栏顶上去 23px 再也回不来——正是「外壳跟着动」那个病换了个入口。`clip` 只裁不滚。

其余不动：侧栏是滚动容器的**兄弟节点**、不是 `sticky`；`lg:` 以下没有侧栏，页面照旧由文档滚动，底部标签栏、`env(safe-area-inset-bottom)`、`pb-24` 全部原样，而且**手机上的文档保留自己的回弹**（那里它就是内容主人）。对话框仍然锁文档滚动（`useDocumentScrollLock`），并由 `.app-locked .main-scroll { overflow: hidden }` 把主区一起钉住。

浏览器实测（headless Chromium / Linux，1280×900，四条路由 × 两套 fixture）：`html`、`body` 的 `overscroll-behavior-y` 是 `none`，文档 `scrollHeight - clientHeight` 恒为 0；把滚轮压在**侧栏**、**顶栏**、**主区**上各连推 40 次，`document.scrollingElement.scrollTop` 恒为 0，侧栏 `getBoundingClientRect().top` 恒为 0，顶栏恒为 0，只有主区的 `scrollTop` 在动。手机上（390×844）文档的 `overscroll-behavior-y` 仍是 `auto`，滚动的是文档。

**这台机器上量不到的那一半**：headless Chromium / Linux 不会复现 macOS 的弹性滚动，所以「回弹」本身没法在这里看见，上面量的是**归属**和**位移**。要在 macOS Chrome 上确认的是两条假设：(a) `overscroll-behavior: none` 落在根元素上会传播到视口并关掉橡皮筋；(b) Chrome 的弹性回弹只发生在**根滚动器**上，非根的滚动容器（也就是主区）在 Chrome 里本来就不弹——所以在 macOS Chrome 上的预期结果是「哪儿都不弹，侧栏和顶栏纹丝不动」，而在 Safari 上主区会弹、侧栏和顶栏仍然不动。如果owner 想要的是「主区必须看得见弹一下」，那就得把结构反过来（文档滚 + 侧栏顶栏 `position: fixed`），那是另一套外壳，代价是卡片等高、容器查询和截图捕获都要重做。

### 0.2 底部标签栏取代汉堡抽屉

四个目的地正好能平铺，所以手机上不再用「汉堡 + 抽屉」：一次点击代替两次，也不需要焦点陷阱。

- `AppTabBar.vue`：`fixed inset-x-0 bottom-0`、`grid-cols-4`、`lg:hidden`。
- 每格 `min-h-11`（44px 触摸下限），`aria-current="page"` 标注当前页。
- 底部内边距带 `env(safe-area-inset-bottom)`，避开 home indicator。
- 用向上的阴影 `.elevate-up`（发丝线 + 反向柔光）。共享的 `--ui-e*` 都朝下投影，贴在视口底部时看不见。
- 侧栏和标签栏共用 `src/utils/navigation.js` 里同一份 `NAV_ITEMS`，顺序即焦点顺序，两处不会漂移。
- 主区在 `lg:` 以下留 `pb-24`，最后一张卡片不会被标签栏压住。

**汉堡按钮与抽屉组件已删除，不得复活**（契约测试会检查 `aria-label="打开导航"` 不再出现在任何 `.vue` 里）。

| 路由 | 标题（`document.title` ＋ sr-only `<h1>`） | 可截图 |

### 0.4 数据从哪来

看板的展示模型由 `src/utils/usageBuckets.js` 从运营商原样返回的 OCS 分组推导。数据管线（`src/composables/`、`src/domain/`、`src/services/`）一行没动：`useUsageDashboard` 本来就允许注入请求函数，外壳借这个口子留一份 `code === "0000"` 的原始响应，视图层再从它推导到期时间、同名条目的返回顺序这些 domain 卡片不带的事实。

### 0.5 一页一张卡片，卡片内部是 band，不是嵌套卡片

「目前每一页都是多个卡片，看起来很零碎」——**四条路由各自只有一张 `AppCard`**。这一轮它变成了唯一的一层：

- **卡片对画布的分界只有一种机制：阴影**（`shadow-e2`），没有描边。理由是这一对 token 已经把两个主题都算进去了——浅色是「1px 接触影 ＋ 一道很宽的环境影」，读起来是纸搁在画布上；深色里阴影本来就看不见，所以 `--ui-e2` 的**第一层就是一条发丝线**。同一个 token，两个主题，一条声明；再加一条 `border` 就是同一件事说两遍。实测（浅色）：`box-shadow: rgba(28,27,21,.06) 0 1px 2px, rgba(28,27,21,.42) 0 12px 26px -14px`，`border-top-width: 0px`。
- **卡片自己不带内边距。** 全宽线必须通到卡片的两条边，所以左右插入量整体下放给每个 band（`px-5 sm:px-6`＝20 / 24px，全项目唯一的一个值）。角落不会再被子元素磨平：卡片自己 `overflow-hidden`。
- **卡片内部没有嵌套卡片。** 区域（`AppSection`）**不带底色、不带描边、不带圆角、不带阴影**。这是 Material 3 的读法：卡片是一个「单一的、被包住的单元」，它内部的分隔手段是 divider，而不是再来一层卡片。上一轮那种「托盘里摆一堆 6px 小卡」读起来是一摞盒子，正是「很零碎」的根因换了个形状又回来了。

#### 分界只有三种，各有各的岗位

| 机制 | 谁画 | 干什么 |
| --- | --- | --- |
| **全宽横线** | `AppCard` 自己的 `divide-y divide-divider` | 分开卡片的 band。条数 ＝ 直接子元素数 − 1，数得清，也没有哪个 band 能偷偷给自己加一条 |
| **接缝网格** | `.ui-seams`（`main.css` 的 `@layer components`） | 并排区域之间的 1px 竖缝，以及同一张网格里行与行之间的 1px 横线。`gap: 1px` 露出 `--ui-divider`，格子铺 `--ui-surface-raised` |
| **行线** | 区域内部的 `border-t border-divider first:border-t-0` | 列表 / 表格的行分隔。它被区域的左右内边距**缩进**，因此一眼就和结构性的全宽线分得开 |

Material 也提醒过：divider 用多了就是噪音。所以规则是**用最少的几条把结构说清楚，剩下的交给留白和标题层级**。实测（1280×900，sparse fixture，浏览器里数出来的）：

| 路由 | band | 全宽横线 | 接缝行 | 接缝列 | 每条线为什么留着 |
| --- | --- | --- | --- | --- | --- |
| `/` 看板 | 4 | **3** | 1 | 6 | 抬头↔主数字（身份和数据）、主数字↔四格事实（3 列 vs 4 列，不分开会读成一张错位的表）、事实↔图区（数字和图是两种东西） |
| `/usage` 用量明细 | 4 | **3** | 0 | 0 | 抬头↔流量、流量↔语音、语音↔短信：三张表各自成段 |
| `/services` 已订业务 | 2 | **1** | 2 | 1 | 只有抬头↔分组网格这一条；分组之间的缝由接缝网格画，不占全宽线的名额 |
| `/settings` 设置 | 1 | **0** | 2 | 1 | 整页就是一张接缝网格，一条全宽线都不需要 |

四条路由一共 **7 条全宽横线**。契约里有一张 `CARD_BANDS` 登记表，加一块 band 必须先在那里报到——也就必须先回答「这条线是不是真的需要」。

#### 还留着的填色和阴影

- **填色只给行内元素**，不给区域：chip、状态徽章、推断徽章、进度轨道、输入框、分段控件的轨道（`--ui-surface-sunken`），以及主 / 警示 / 危险的 container 色。
- **阴影只给真正的浮层**：账号菜单、`AppToast`、`LoginDialog`、`PrivacyModal`，加上页面卡片自己那一层（那是它的「边」）。分段控件选中的那一格、主按钮、侧栏的品牌标以前都挂着 `shadow-e1`，这一轮全部去掉——它们靠色阶站住，而色阶是被契约钉死的。

### 0.5.1 `--ui-surface` 去哪了

旧的「托盘色」是「卡片 vs 卡片里的小卡」这一对的产物。卡片内部不再有小卡，这一对就不存在了，所以 **`--ui-surface` 和 `--color-surface` 都已从 base.css / main.css 删除**，不是留着不用——留一个没人用的 token，下一轮补丁就会拿它再造一层。契约里有一条断言直接盯死这件事（`bg-surface` 在任何 `.vue` 里出现即红）。

它在色板里的两个原始档位一并处理：`--paper-05`（浅）删掉；`--night-10`（`#2a2925`）**改绑到深色的 `--ui-surface-sunken`**——旧值 `#161513` 比画布还暗，一枚 chip 读起来像在页面上挖了个洞；`#2a2925` 落在画布和卡片之间，凹的是**相对卡片**。实测卡片 `#3a3935` vs sunken `#2a2925`：1.259× / ΔE 7.4（门槛 1.2 / 6），三档墨在它上面 11.47 / 8.59 / 6.79，`outline` 3.84，三支分类色 4.79 / 4.38 / 4.70，全部过。

### 0.5.2 页面卡片在四条路由上是同一个矩形

- 同上边——`main` 的 `pt-4 lg:pt-6` 对四条路由一视同仁；
- 同宽、同左边——`mx-auto w-full max-w-[76rem]`；
- 同高的**下限**——捕获容器 `lg:min-h-full` ＋ 卡片 `lg:grow lg:min-h-0`：内容短的一页补白落在卡片自己里，而不是缩成一小块。

浏览器实测（1280×900，sparse fixture）：四条路由的 `top` 恒为 80、`left` 恒为 280、`width` 恒为 984、`height` 恒为 804。

**为什么是下限而不是上限。** 试过把它钉成 `lg:h-full`：1280×900 上确实连主区都不用滚了（rich fixture 从溢出 229px 变成 0），代价是右列那两块到期分组图被裁在半行上，连刻度尺一起裁掉——一张靠刻度读数的图，裁掉刻度就等于图没了。补救的 `sticky` 刻度尺更糟：滚动时它把上一条 lane 拦腰盖掉半行，读起来是渲染出错。所以规则回到下限：**典型账号（sparse）在 1280×900 上不需要滚整页（实测主区溢出 0px）；数据特别多的账号（rich，8 个流量包）主区滚 229px**，而单块内容特别长时仍然由区域在自己内部滚（§0.7）。

导出图不继承这个拉伸也不继承任何天花板：`.is-capturing { height: auto; min-height: 0 }` ＋ `.is-capturing .app-section / .pane-scroll { max-height: none; overflow: visible }`（`main.css` 末尾的不分层规则）。

### 0.6 同一行的兄弟区域必须齐底

规则来自需求原话：**内容短就补白，内容超出就在区域内部滚动，区域本身不长高。**

这一轮它变成了**布局的性质而不是额外的约定**：接缝网格的格子天然等高（`align-items: stretch`），所以「齐底」不需要任何一条额外的 class。

- 看板的图区：`CHART_BAND` ＋ `CHART_CELLS`（都在 `src/utils/ui.js`）。流量占满左列的两行（`row-span-2`），语音和短信各占右列一行。DOM 顺序就是手机上一列到底的阅读顺序。骨架屏 `import` 的是**同一份常量**，所以「数字落地时不跳」是结构性的，不是两处抄写碰巧一致。
- 已订业务：`@[48rem]:grid-cols-2`，每个分组一格，按条目数从多到少排（「其他业务」永远压最后）。
- 设置：`@[60rem]:grid-cols-2` ＋ `grid-rows-[auto_auto_1fr]`——前两行按内容高度排，留白全部给最后一行。均分给六个格子会在每一组下面各挖一个洞（试过，是这一轮第一版的样子）；留在卡片外面又会让卡片下半截读成「多了一块空区域」。
- **奇数个格子必须把最后一格拉满整行**（`@[48rem]:odd:last:col-span-2` / `@[60rem]:col-span-2`）。接缝网格的**底色就是分隔线色**，空出来的那一格会露成一整块分隔线色的矩形，而不是一道缝。契约钉死了这一条；健壮性回归里用「格子面积 ÷ 网格面积 ≥ 0.9」逐个网格量过，14 个场景全部无洞。
- **天花板压在「滚动主体」上，不压在区域自己身上**（`AppSection` 的 `body-class`）：流量 `max-h-176`（704px），语音和短信各 `max-h-80`，业务分组 `max-h-96`，设置的账号区 `max-h-96`。压在区域身上时，区域就拉不到整行的高度，一行里两块的高度会变成「谁先撞到自己的上限」说了算（实测过：十二条 lane 时两列底边差 58px；视口 980px 高时语音区域比它那一行短 49px）。
- 补白落在哪里是设计过的：坐标轴用 `mt-auto` 钉在区域底边，空白落在条形和刻度之间；空态 `EmptyNote` 用 `my-auto` 居中。
- **手机上不做等高**：容器查询断点以下是单列，区域按内容堆叠。

### 0.7 内部滚动的可发现性

一个会截断内容的区域必须承认自己在截断：

- `.scroll-shade`：两层 `local` 的遮罩渐变 ＋ 两层不动的阴影，只有**真的裁掉了东西的那一边**才画得出阴影。纯 CSS，改窗口不会失效。遮罩色就是卡片色（`--ui-surface-raised`）。
- 只有真的溢出时才挂 `tabindex="0"`、`role="region"` 和中文 `aria-label`（`usePaneOverflow` 用 `ResizeObserver` 量出来，不靠猜），没溢出就不留死的 tab 停靠点。
- 区域**不写** `overscroll-behavior`：滚到头必须把滚动交还给主人（见 §0.1.1 的第四种角色）。
- 刻度尺**不做 sticky**：它必须和条形待在同一个内容盒里一起滚，否则滚动时它会把上一条 lane 拦腰盖掉半行。

## 1. 基础机制

- 颜色写在 `src/assets/base.css` 的 `--ui-*` 上，`:root` 是浅色，`.dark` 覆写深色。
- `src/assets/main.css` 用 `@theme inline` 把 `--ui-*` 映射成 Tailwind 颜色名。
- **不要写 `dark:` 颜色类。** 同一个类名在两个主题下自动换值；写 `dark:` 等于把主题逻辑复制到组件里。
- `@theme` 里显式清空了 Tailwind 的默认字号与圆角（`--text-*: initial; --radius-*: initial;`）。`text-sm`、`rounded-xl` **不存在**，写了也不会生成 CSS。

六件事被钉成断言：

- **相邻表面的最小步进**（§2.1.1），以及**外壳同侪的那一档**（§2.1.3）——两条一起钉，只钉一条的话，「修」其中一条的方式就是违反另一条。
- **卡片必须在画布的两端都站得住**：≥1.08× / ΔE 3.5。旧的托盘色在这一对上实测只有 **1.001×**，卡片的上边缘等于没有边；现在浅色 1.112× / ΔE 4.4（最亮端）、1.163× / ΔE 6.2（最暗端），深色 1.298× / ΔE 8.5 和 1.579× / ΔE 17.2。
- **凹陷那一档必须真的读成凹下去**：`surface-sunken` 对卡片 ≥1.2×。浅色 1.335× / ΔE 12.2，深色 1.259× / ΔE 7.4。
- **分隔线必须真的看得见**：ΔE ≥ 8。1px 的发丝线不适用图形的 3:1（那会画出一条黑杠，Material 自己的 divider 也在 1.3–1.6× 一带），量的是感知色差——浅色 ΔE 21.2、深色 ΔE 13.9。这条是这一轮新加的，因为分隔线现在是卡片内部**唯一**的结构性分界。
- **每一块表面都必须是暖的**（R > B），并且卡片 ≠ `#ffffff`。
- **12px 墨在 hover 覆盖层之下也要过 AA**，量的位置精确到「真的会画 hover 覆盖层的那几块面」：卡片、凹陷、侧栏。

`on-surface-muted` 的深度是被 12px 逼出来的：它必须在**它真的会落上去的每一块表面**上、并且在 hover 覆盖层之下都过 AA。这份清单里包含侧栏那块合成出来的表面（半透明纸色铺在会变的画布上，两端都要过），但**不包含画布，也不包含顶栏**——见 §0.1。

这一轮还补量了 `on-warning-container`：「数字对不上」那两句降级提示是画在**卡片**上的正文，不是画在琥珀色容器里的，旧契约只量了它在容器上的那一种用法。实测卡片上 7.46（浅）/ 8.13（深），凹陷上 5.59 / 12.83，侧栏两端 6.90–9.72，hover 之下最低 4.89，全部过 AA。

`divider` 和 `outline` 是两件事，不要混用——发丝线不需要 3:1，输入框边界需要。`rule` 是第三件：它只属于顶栏那条常驻分界线（§0.1）。

### 2.1.1 相邻表面的最小步进：两块面贴在一起，就得看得出来

「侧栏里选中的那一项发闷」「主卡片的上边缘化进了背景」不是两处走查漏掉的地方，是同一条规则缺失的两个症状。**根因是画布会变**：它带了两道 wash，所以「按 token 值算出来成立」的步进，会在 wash 把画布推到卡片色附近的那一带失效。实测（1280×900，浅色，直接采合成后的像素）：

| 相邻的一对 | 修之前（最差点） | 修之后（最差点） |
| --- | --- | --- |
| 画布 / 外层卡片 | **1.001×**（卡片上边缘等于没有边） | 1.341× |
| 画布 / 侧栏 | 1.029× | 1.371×（同高度取样） |
| 侧栏 / 当前导航项 | **1.051×**（就是「发闷」） | 1.241× |
| 外层卡片 / 嵌套区域 | 1.171× | 1.206× |
| 画布 / 顶栏的次按钮 | 1.111×（**没人报，但病是同一个**） | 1.341× |

（这张表是**上一轮**的记录，留着是因为那几个数字解释了规则为什么存在。这一轮的前后对照在 §2.1.3；顶栏的次按钮从那以后不再站在画布上，它站在顶栏自己的那块面上。）

规则本身：

> **任何两块贴在一起的表面，必须同时满足对比比值 ≥ 1.20× 和 ΔE\*ab ≥ 6，并且是在两者各自的最糟点上成立。**

- **为什么是两把尺子。** 对比比值是这份文档其余部分说的话，但它在近白和近黑两端的感知含义不一样；ΔE\*ab 是感知均匀的，而且带上了色相——一枚珊瑚色的 chip 铺在米色上，亮度只差 1.06×，但 ΔE 有 10.8，它确实分得开。带色相的一对（状态徽章、遮罩）因此只钉 ΔE。
- **为什么是 1.20 / ΔE 6 而不是原来的 1.15。** 上一轮的 1.15 和 1.2 都写在 token 上，而失效的是**渲染出来的最糟点**（量到 1.001×），所以先修的是量的位置。数值本身选在 ΔE≈6：ΔE 2–3 只在正视、并排、盯着看的时候才分得出，6 是「一台没校准的笔记本屏、偏着头看仍然分得出」的一步，换算到这套梯子的两端正好落在 1.20× 附近。
- **wash 的振幅因此不是自由的。** 契约把两道 wash 在满强度下合成到画布上，取最亮的那一端来判定；更早的一轮暖 wash 是 `rgb(255 252 243 / .7)`，合成出来**比卡片还亮**，卡片的上边缘就是这么消失的。这一轮它又多了一个**下限**，见 §2.1.2。
- **画布因此不是文字表面。** 三级 1.20× 的梯子从近白往下走，画布只能落在 12px 墨的 AA 之下。这一轮画布抬亮之后重新量了一遍：最亮的一端 **4.74:1**（刚过），最暗的一端 **3.91:1**（仍然不过）。也就是说这条禁令**没有过期**，只是理由要写成「在最糟点上不过」而不是「在某一点上不过」。让出来的仍然是「文字可以写在画布上」这件事——项目里本来就没有一处这么干。契约把它反过来钉死：**任何 `.vue` 都不许在 `bg-background` 上写文字颜色**，顶栏同理（§0.1），同时把侧栏那块合成表面加进文字表面清单（它是真的在承载文字）。14px 的 `on-surface-variant` 在画布最暗点是 5.26:1、`on-surface` 是 9.49:1，所以这条禁令是**规则上的**保守，不是每一档墨都不行——但一条「哪一档可以哪一档不行」的规则没人记得住，而且 12px 才是这套语言里最常用的那一档。
- **焦点环也落在画布上**（侧栏的导航项站在画布上，顶栏的按钮站在 veil 上），所以浅色的 `--ui-focus` 从 `clay-500` 下调到 `clay-600`，在画布**最暗**的那一角仍然过 3:1（这一轮画布抬亮后实测 3.51:1，比上一轮的 3.34 还宽）。契约现在同时量画布两端和两层 veil 两端。
- **「图」不只是表面。** 同一条规则这一轮又抓到两个没人报的实例，都是「一块色块贴在另一块色块上，看不见」：
  - **骨架块**旧值和 chip 共用一个 token，于是它在当时那两块面上只有 **1.109×（浅）** / **1.151×（深）**——加载态里唯一的图形，等于没画。现在它有自己的一档（`paper-15` / `night-45`），在卡片上实测 1.472× / ΔE 16.6（浅）、1.287× / ΔE 7.2（深）。
  - **推断徽章**（`warning-container`）旧契约只量了状态徽章那两枚。现在三枚徽章都在表里，而且都画在同一块面（卡片）上——卡片里已经没有第二块面了。

被枚举并逐条断言的相邻对（两个主题、最糟点）：画布/卡片、卡片/区域、区域/chip·轨道·输入框、画布/侧栏（两端）、画布/顶栏（两端）、侧栏/当前项、顶栏/栏上的按钮、画布/底部标签栏、区域·侧栏·顶栏/hover 覆盖层、卡片/状态徽章（`primary-container`、`danger-container`）、区域/推断徽章、区域·卡片/骨架块、对话框/被遮住的页面、页面/它自己的遮罩。

### 2.1.2 画布能有多亮：天花板是算出来的，亮起来的办法不是抬那个数

「画布太深了」。直觉的修法是把 `--ui-background` 调亮，但那一步会**原样复活**上一节刚修掉的缺陷——画布正是因为「卡片的上边缘化进了背景」（实测 1.001×）才被压下去的。

先把天花板算清楚。梯子是三级 1.20×，从最上面那一档往下走：

```
嵌套区域（暖近白，R>B）  Y ≈ 0.983   ← 再往上就是纯白，而纯白不是暖色
  ÷1.20 → 外层卡片        Y ≤ 0.800   ＝ #ebe7dc
  ÷1.20 → 画布最亮点      Y ≤ 0.658   ＝ #d9d3c1
```

**所以画布的最亮点只能到 `#d9d3c1`，比上一轮的 `#d8d2bf` 只高 2/255。**这不是取舍，是算术：往上没有第四档纸色可用了。梯子这一轮已经整体上移两级（区域 `#fdfbf6→#fffdf8`、卡片 `#eae6db→#ebe7dc`），把这 2/255 全部吃掉了。

真正让屏幕变亮的是另外三件事，一件都不能少：

1. **把底色顶到天花板减去 wash 的振幅。** 上一轮的画布是「一块很暗的底 ＋ 一道很强的暖 wash」（底 `#c2bca9`，暖 wash 抬 22/255），于是只有左上角那一小片是亮的，其余大部分屏幕就是那块很暗的底。现在反过来：底 `#c9c3b0`，暖 wash 抬 16/255，最亮点仍然顶在天花板上，**底本身高了 7/255**。
2. **把「深」的那道 wash 从一个角改成一层收口。** 浅色里它一直很弱（0.28 的强度只把底往下带 2–5/255，右下角实测 `#bdb6a3`——那一角之所以暗，是**底**暗，不是它挖的）；深色里它正相反：0.35 铺在一块本来就接近纯黑的底上，等于把亮度直接砍掉三分之一，`#060605` 被压成 `#030303`，那才是「一块黑洞」的来源。现在两边分别是 0.16 / 0.14，只留一点点收口。
3. **把屏幕上最大的一块裸画布盖掉**：顶栏那 1016×56 以前就是画布本身，现在是 veil，实测浅色 `#c7c1ae→#d2ccb9` 变成 `#dad5c7→#e0dbcd`（两端 **+19 / +14**），深色 `#090807→#0f0e0c` 变成 `#1e1c19→#22201c`（两端 **+21 / +19**）。

实测（1280×900，rich fixture，`/`，直接采合成后的像素，同一套取样点）：

| 量 | 浅色 前 → 后 | 深色 前 → 后 |
| --- | --- | --- |
| 画布可见范围 | `#bdb6a3 → #cac5b2` ⇒ `#c4bdaa → #cec8b6` | `#030303 → #0d0c0a` ⇒ `#0d0c0c → #151412` |
| 最暗的那一角 | +7/255 | +10/255 |
| 顶栏那一条 | `#c7c1ae→#d2ccb9` ⇒ `#dad5c7→#e0dbcd` | `#090807→#0f0e0c` ⇒ `#1e1c19→#22201c` |

**代价要说清楚：这三件事互相抢同一段亮度。** 底越高，暖 wash 能抬的振幅就越小；而暖 wash 的振幅正是侧栏「透」出来的那点变化的唯一来源（§16.1）。所以 wash 现在**两头都有界**：上界是「合成到最亮点不许够到卡片」，下界是「暖 wash 的振幅 ≥ 8/255」——低于这个数，半透明就退化成 §16.1 里那个被否掉的空操作。契约两条都钉。为了在收窄的振幅下保住侧栏采到的变化，暖 wash 的几何也改了：从 `72% 62%` 拉宽成 `128% 58%`，横向铺开、纵向收紧，侧栏那 264px 宽度上的取样点因此落在渐变更靠中心的位置。最终实测侧栏自身沿高度的变化 **6/255（浅）/ 4/255（深）**，上一轮同一套取样点是 8/255 与 4/255。

### 2.1.3 外壳同侪：ΔE ≥ 6 是给图和底的，不是给一家人的

「顶栏没有自己的背景，它应该和侧栏一样，只是稍微区分一下。」这句话和 §2.1.1 直接顶：侧栏和顶栏在左上角相接，是一对相邻表面，而 ΔE ≥ 6 恰好会逼出 owner 明确不要的那种差异。

缺的是一个类别。**ΔE ≥ 6 的意义是「让人能把图从底上分出来」**；两块**本来就属于同一层外壳**的面之间不存在图和底，它们要的是「看得出是两块，但一眼就知道是一家人」。所以：

> **外壳家族＝画布 ＋ 铺在它上面的两层 veil（侧栏、顶栏）。家族内部的步进由「谁和谁」决定，不由 ΔE 6 决定：**
>
> - **veil 对画布**（侧栏/画布、顶栏/画布）：veil 是**铺在**画布上的一层，它必须读成自己的一块面（「侧栏是一块自己的区域」是需求原话）。钉 **≥1.10× 且 ΔE ≥ 4**，两端都要成立。**不设上限**——真正封住它的是下一条。
> - **veil 对它承载的东西**：侧栏承载文字（三档墨在它两端都过 AA），顶栏承载控件（控件的纸色必须比它高 **1.20× / ΔE 6**）。这两条才是 veil 亮度的上界，而且它们是**图/底**规则，不是同侪规则。
> - **veil 对 veil**（侧栏/顶栏）：同侪。钉一个**两头都封死**的带：**2.5 ≤ ΔE ≤ 5.5**，两端都要成立。下限是「一台没校准的笔记本屏上，两块贴着的大面积色能看出是两块」（而且它们中间还有侧栏那条 `border-r` 发丝线兜底）；上限**严格小于 6**——到了 6 顶栏就不再是侧栏的同侪，而是另一块东西。
>
> 除此以外的每一对相邻表面，仍然走 §2.1.1 的 **≥1.20× 且 ΔE ≥ 6**。

两条规则必须**一起**钉在契约里，这是这一节存在的全部理由：只钉一头的话，下一个人「修」其中一条的最省事的办法就是违反另一条。契约里因此有三样东西：`SURFACE_PAIRS`（图/底，含 veil 对画布的下限和 veil 对控件的上限）、`SHELL_PEERS`（同侪的带，上下限各一条断言）、以及一条「两层 veil 必须是同一个 rgb 三元组、只有 alpha 不同，且顶栏必须更薄」的结构断言——同侪关系不是「两支碰巧接近的颜色」，是**同一层纸的两个厚度**。

### 3.1 粗细：两档，而且 600 几乎不花

「加粗的字体太多了，一眼看过去很密集，抓不住重点」——问题不是有粗体，是**处处都是粗体**，于是强调不再意味着任何东西。规矩收成三条，全部钉成断言：

1. **只有 400 和 600。** `font-bold` / `font-medium` / `font-light` / `font-normal` 一律不存在；模板里也不许出现 `<b>` / `<strong>`（UA 默认粗体是同一个漏洞）。
2. **600 的第一个来源是三个大字号自带的。** `title` / `display` / `hero` 天生 600，它们的语义是「这一块叫什么」和「这一屏的主数字」。**一块区域里只有一个**：区域标题；lane 里只有一个：那条 lane 的合计。
3. **600 的第二个来源是手写的 `font-semibold`，而它只允许出现在五个文件里，且必须是「当前/主要的那一个」的控件状态**：侧栏的当前导航项（和产品名）、标签栏的当前项、顶栏的主按钮、设置页的主按钮、主题分段控件的选中项。除此以外一处都没有。

推论——**任何 14px / 12px 的数据文字都不加粗**：lane 的到期日期、条形的分段标签、明细表的资源名、面板抬头的「合计」、状态徽章、推断徽章，全部是 400，靠**墨色的一档**（`on-surface` vs `on-surface-variant` vs `on-surface-muted`）区分主次。

浏览器实测（1280×900，rich fixture，浅色，统计卡片内部真正渲染出文字的元素）：

| 路由 | 改前 600 的元素数 | 改后 |
| --- | --- | --- |
| `/` 看板 | 59 | 20 |
| `/usage` 用量明细 | 20 | 4 |
| `/services` 已订业务 | 9 | 8 |
| `/settings` 设置 | 7 | 7 |

看板剩下的 20 个是：卡片标题 1 ＋ 三个概览数字 3 ＋ 四个参数值 4 ＋ 四个区域标题 4 ＋ 每条 lane 的合计 8。每一个都是「这一块里真正重要的那一个」。

### 3.2 「文字过于密集」是怎么修的：动行距和节奏，不动字号

**字号一格没动**，还是 12 / 14 / 17 / 22 / 34。上一轮正因为「你把所有的内容都做那么大干嘛」被否掉过。真正动的是四件事：

1. **行距**。三个小档开到 1.50 / 1.57 / 1.53 倍（18 / 22 / 26）。中文在 12px 上最吃行距，这是密集感的主要来源。契约测试把「三个小档 ≥1.45 倍」钉死。
2. **字距**。只给最小的一档 `+0.01em`。
3. **内边距与节奏**，现在只有**一层**：卡片自己不带内边距（全宽线要通到两边），区块 `px-5 sm:px-6`，文字到卡片外沿就是 **20 / 24**——当初定死的那个值，一分不欠也一分不多。契约按 band 逐个量，任何 ≥16px 的横向内边距只许是这一对。lane 之间 `pt-3 pb-2.5`；概览格子 `py-4`；四格参数 `py-3`；明细行 `py-2.5`。全部仍是 4 的倍数。
4. **减少同时出现的文字块**，这条比前三条都管用：图表的长说明挪进标题的 `title`；lane 的抬头拆成两行（到期时间和合计永远同行，包名和 chip 单独一行）。

### 3.3 备注与说明文字：只留推不出来的那一句

「你的备注标注文字太多了，这也是之前导致首页看着很乱，信息很密集的原因之一。」每一句次要文字只有三种下场：

| 判断 | 处理 |
| --- | --- |
| 屏幕上已经写着了 / 从旁边的数字直接推得出来 | **删** |
| 是一次性的说明（规则、依据、口径），第二次进来不需要再读 | 挪进最近那个控件或标题的 `title` |
| 是这一页无法从别处得知的事实，或者是正确性披露 | 留在屏幕上 |

按这个判断逐条走完四条路由，删掉的和搬走的：

| 位置 | 原文 | 处理 |
| --- | --- | --- |

**明确保留**：「本月底作废（推断）」徽章和它的 `title`（正确性披露，见 §8）、QCI 与签约速率的 `title`、整组同名时的编号说明（同名条目的身份规则，见 §9.2）、三种空态的两句话（§7）、登录页的授权说明。

规则钉成断言的方式是结构性的：**四条路由的模板里不许出现「写死的、以句号结尾的整句」**。事实要么进 `title`，要么进 `EmptyNote` 的 props（空态那三句是这么传进来的），要么就该删。

## 4. 图表

三张图，全部是**当前余量的快照**，没有一张重建了时间序列——本机不存历史。

### 4.1 流量 / 语音 / 短信按到期时间分组（`ExpiryLanes.vue`）

这是整套设计的核心：**按到期时间分组，从结构上消灭重名问题**。三个都叫「语音」的条目不再是三行需要辨认的重复项，而是按「什么时候作废」落进两条 lane。

- **一条 lane = 一个到期时间**。lane 顺序即紧迫度：本月内 → 有到期日（日期升序）→ 长期有效 → 到期未知。
- **条长 = 绝对额度**，所有 lane 共用一把从 0 开始的刻度，上界由 `niceScale()` 取到人读得出的整数（60GB / 1000 分钟，而不是 78.13GB）。刻度尾数只取 1 / 1.5 / 2 / 2.5 / 3 / 4 / 5 / 6 / 7.5 / 8 / 10。
- **一条 lane 里按返回顺序铺开每个包**：先画剩余段（到期色阶），再画已用段（`spent` 灰）。相邻段之间留 2px 缝，缝从后一段身上扣，**起点不动**，刻度才准。窄于 0.6% 的已用段不画色块——那已经只剩一根线了——改由文字「全月只用掉 X」交代。
- **每段配一个印出来的标签**。放得下就贴在段起点（≤3 个标签、彼此间距 ≥26%、最后一个不超过 72%），否则整行退回可换行的清单。两个数字永远不会叠在一起。
- **编号 ①②③** 只在需要区分时出现：整组同名（卡头只报「N 个包」）或一条 lane 里不止一个包。卡头已经逐条列了名字和编号时不再重复。
- lane 抬头是两行：**第一行是到期文案 ＋ 这条 lane 的合计**（`text-title`，靠右），第二行才是包名和 chip。只有一条 lane 时卡头的「合计」隐藏——同一个数字不印两遍。
- 那句「条长＝绝对额度，0–80GB 共用刻度……」不再占标题行，挪进了面板标题的 `title`：事实还在，标题行不再三块挤一行。
- 区块底部（`AppSection` 的 `#footer`，永远在最下、不随内部滚动跑掉）：不限量资源的脚注、整组同名时的编号说明。对不上账的告警贴在出问题的那条 lane 下面。

### 4.2 「本月消耗去向」为什么被删掉

它和「流量按到期时间分组」问的是同一件事。到期 lane 里每一个包本来就画着**剩余段 ＋ 已用段**，并且逐条印着「剩余 4.80GB · 已用 10.20GB」；点图只是把同一批已用量换成一维的点再画一遍。一屏之内同一个数字出现两次，正好撞上第 5 条原则。

- 它唯一独有的信号是「哪些包这个月动过」。这个信号**留在 lane 里**：动过的包有一段灰色的已用段，也有印出来的「已用 X」；没动过的两样都没有。不为它另开一块面板，也不加替代图。
- `SpendDotPlot.vue` 已删除，`buildUsageModel` 不再产出 `spend`，对应的模型测试一并删掉。看板的 grid 从 2×2 变成「左列跨两行 ＋ 右列两格」（§0.6）。
- 顺带解决的是 §3.3 的密度问题：整块面板连同它的标题、合计、坐标轴、行名和一句 summary 一起消失。

### 4.3 概览条（`DashboardHero.vue`）

单值对上限，是仪表不是图表，全项目只有一个 `ProgressTrack.vue`：6px 高、`rounded-chip`、`bg-surface-sunken` 轨 ＋ **这一格资源种类的分类色**填充（`series-1/2/3`，见 §2.4），配 `role="img"` 的可读名。填充色跟着 `section.id` 走，不跟着它排到第几格。没有分母（全是不限量、或一条都没有）时不画条。用量明细每一行的「剩余占比」条同理；不限量的行保留同一个色，只是加一层 `.progress-unlimited` 的遮罩扫过，不另给颜色。

### 4.4 图表的无障碍

- 每条 lane 的轨道是 `role="img"`，`aria-label` 就是「到期文案 + 合计 + 每段数值」。
- 每个色块带 `title`；色块本身 `aria-hidden`，因为它旁边就印着同样的数字。
- 颜色从不单独承担信息：到期由 lane 标题的文字给出，已用/剩余由标签给出，资源种类由格子的标题和 `aria-label` 给出。
- 几何变化用 `.chart-animate`（只过渡 `width`/`left`/`transform`），`prefers-reduced-motion` 下降到 1ms。**没有任何循环动画。**

## 5. 圆角

| 类名 | 值 | 用途 |
| --- | --- | --- |
| `rounded-card` | 8px | **只有页面卡片**、对话框、下拉面板 |
| `rounded-control` | 6px | 按钮、导航项、账号行、输入框、分段控件（轨道和格子同档）、品牌标、对话框抬头的徽章、第三方内容的井 |
| `rounded-chip` | 4px | chip、状态徽章、进度条、条形色块 |
| `rounded-dot` | 50% | 只给真正的圆：状态点、账号头像、图标钮、加载圈 |

**卡片内部的区域没有圆角**——它们不是卡片（§0.5）。「越里越圆」和「往上加一档（12 / 16px）」都是错的方向，「圆角弧度太大」被明确否掉过。状态点用 `rounded-dot` 而不是 `rounded-chip`：4px 圆角画在 6px 的方块上，那不是一个点。

角落限定形式（`rounded-t-card`）可以，但必须落在这四个名字上。

## 6. 间距与高度

- 间距只用 4 的倍数。**卡片之间已经没有间距了——一页只有一张卡片**，而且**卡片自己不带内边距**（全宽线必须通到两边）。
- **横向插入量全项目只有一个值：`px-5 sm:px-6`（20 / 24px）**，由每个 band 自己带上。抬头 band、区块标题行、区块滚动主体、区块脚注、主数字格、事实格、骨架块——全部同一个值，所以每一行文字的左边缘都落在同一条竖线上。契约按 band 逐个量：**任何 ≥16px 的横向内边距只许是 `px-5` 或 `sm:px-6`**（判据是圆角——band 永远没有圆角，有圆角的一定是控件）。
- 竖向节奏：抬头 band `py-3 sm:py-4`，区块标题 `pt-4 sm:pt-5` ＋ `pb-3`，区块主体 `pb-4 sm:pb-5`，主数字格 `py-4`，事实格 `py-3`。
- 主区外边距 `px-4`、上边 `pt-4 lg:pt-6`、下边 `pb-24 lg:pb-4`；顶栏用同一个 `lg:px-4`。
- 高度：

| Token | 用途 |
| --- | --- |
| `shadow-e1` | **只有 `AppToast`** |
| `shadow-e2` | **只有页面卡片**——它同时就是这张卡片对画布的**唯一**分界机制 |
| `shadow-e3` | 对话框、下拉面板 |
| `.elevate-up` | 底部标签栏（向上投影 + 发丝线） |

浅色下是「1px 接触阴影 + 大范围强偏移柔光」的两层组合，这一对才让卡片读起来是**搭在纸上**而不是从纸上挖出来的。深色下阴影几乎读不出来，所以每一级额外画一道发丝线——`--ui-e2` 的第一层就是那条线，这正是「一种机制覆盖两个主题」的来源。

**卡片内部一律没有阴影。** 上一轮主按钮、分段控件选中的那一格、侧栏的品牌标、进度轨都挂着 `shadow-e1`，这一轮全部去掉：它们靠色阶站住，而色阶是被契约钉死的。契约反过来盯：除了外壳和四个浮层，任何 `.vue` 里出现 `shadow-e*` 即红。

## 7. 空态规则

空态是一条结论，不是一个缺口。三种情况必须分开说：

| 情况 | 判据 | 文案 |
| --- | --- | --- |
| 运营商返回 0 条 | 分组存在、条目数为 0 | 「本套餐不含 X 资源」+「运营商在 X 分组下返回 0 条记录：既不是查询失败，也没有可用余量。」 |
| 压根没返回这个分组 | `section.present === false` | 「未取到 X 分组」+「可稍后刷新重试；这与『套餐不含 X』不是一回事。」 |
| 有条目但都没有额度 | 只有不限量 / 额度为 0 | 「没有可分组的 X 资源」+ 说明两种可能 |

短信在样板账号里是**有意的空态卡片**，不是一块缺失的磁贴：它和「查询失败」是两回事，文案必须把这句说出来。

统一用 `EmptyNote.vue`。它**不再是一块填色的盒子**——卡片内部没有嵌套面，一条结论靠字号层级和留白站住就够了：标题 `text-title text-on-surface-variant`，正文 `text-caption leading-relaxed text-on-surface-muted`，整块 `my-auto` 在区域里居中。

## 8. 推断出来的结论必须承认自己是推断

QCI 已经立了规矩：接口给了就直接印 `8`，推断出来的印 `8（推断）`。看板上的到期分组沿用同一条规矩。

- **「本月底作废（推断）」** 是从资源名里的「上月结转限本月使用」推断的，联通接口没有这个字段。
- 用 `InferredTag.vue` 渲染：`warning-container` 底 + 三角图标 + 12px 600 文字，`title` 里写明推断依据。`hint` 是必填 prop——没有依据的推断不允许出现。
- **运营商换了措辞就立刻退回**按接口的 `endDate` 分组，绝不继续声称一件已经无从判断的事。
- 拿不到 `endDate` 时落到「到期时间未知」，既不说长期有效也不说快到期。

## 9. 三条数据正确性规则

1. **`本月底作废` 是推断，不是接口字段。** 见上一节。
2. **同名条目的身份是 `(名称, 总量, 到期)`**，三项全撞才退回下标（`key#index`）。绝不只用数组位置——否则刷新一次 ①②③ 就换了意思。编号本身按运营商返回顺序分配，并在卡片上写明这条规则。
3. **绝不假设 `剩余 + 已用 = 总量`。** 误差超过 1%（且绝对值 >1）就判为对不上：条形按总量钳位（剩余封顶到总量，已用填到剩余之后的余量），同时在 lane 下方和用量明细底部用 `warning` 徽章明写「剩余 X 加已用 Y 对不上总量 Z，条形按总量钳位显示」，运营商原样返回的数字照印不误。

不限量的包没有分母：**永远不进任何占比图**，不进合计，占比列显示「不限量」而不是百分比。它的绝对已用量在到期条卡片底部单列一行脚注，用量明细里照常逐条印出来。

## 10. 收敛层：一个图形，一个出处

「你现在改的太乱了，每个地方都是单独打补丁。你应该把所有的样式都进行统一收敛管理。」

审计的结果：22 个 `.vue` 里有 **229 条互不相同的多 token class 串**，其中 **43 条逐字出现在一个以上的文件里**。最扎眼的几处——账号行在顶栏菜单和设置页是**逐字相同**的两份 markup；按钮有四套写法（设置页一组常量、顶栏另一组常量、登录对话框六串手写、隐私说明两串），连指针高度都分成 36px 和 40px 两档；焦点环在 11 个文件里手写了 19 遍，其中 6 处外扩、5 处内嵌，凭的是当时改到哪一个；分段控件两份实现，一个 8px 圆角一个 6px、一个给当前格加了 600 一个没加；骨架屏三份实现；`DashboardHero` 的两段 grid CSS 被 `DashboardSkeleton` 在自己的 `<style scoped>` 里抄了一份。

收敛之后：**196 条 / 22 条跨文件**，剩下的跨文件项要么是共享常量的两个 import 点，要么是 2–3 个 token 的字号 ＋ 墨色对（那是排版词汇本身，不是「图形」）。

### 10.2 配方：只有 class 串重复的那些（`src/utils/ui.js`）

```js
TRANSITION      // 颜色过渡：全项目一种时长一条曲线
HOVER_OVERLAY   // hover / active 覆盖层。选中态不叠它
DISABLED        // 禁用态
FOCUS_RING      // 焦点环，外扩：控件四周有余量（按钮、图标钮、输入框）
FOCUS_RING_INSET// 焦点环，内嵌：控件贴着容器边（导航项、账号行、分段格）
BUTTON_BASE     // 按钮底座：h-11 … rounded-control px-4 … sm:h-9
BUTTON_VARIANTS // filled / outlined / text / danger / shell
HEADING_ROW     // 标题行 ＋ 唯一的横向插入量 px-5 sm:px-6
PAGE_TITLE      // 抬头标题的字号：text-title … sm:text-display
ICON_BUTTON     // 只有图标的按钮（对话框关闭）
NAV_ROW         // 一行可点的条目
HERO_BAND / FACT_BAND / CHART_BAND / CHART_CELLS  // 看板的 band 与落位；骨架屏 import 同一份
```

CSS 那一侧只有一条，因为它是「一个容器的行为」而不是一串 class（`main.css` 的 `@layer components`）：

```css
.ui-seams      { display: grid; gap: 1px; background-color: var(--ui-divider); }
.ui-seams > *  { background-color: var(--ui-surface-raised); }
```

调用方只加列数和落位，**不许再加 `gap-*`**（那会把接缝抹掉）。

**焦点环选哪一种是一条写下来的规则，不是感觉**：控件四周有余量用外扩，控件贴着容器边用内嵌（否则环会被相邻元素或容器的 `overflow` 裁掉）。

### 10.3 用法


### 13.1 覆盖层怎么关：一个共享原语，四条关闭路径

「右上角的账号菜单点外面不关、按 Escape 也不关」。两个根因都不是这一个菜单的问题，都是**类**问题：

1. 那个铺在页面上的「透明遮罩按钮」写的是 `fixed inset-0`，但它的定位祖先是带 `backdrop-filter` 的顶栏——**任何非 none 的 `backdrop-filter` / `filter` / `transform` 都会给 `position: fixed` 的后代造出新的包含块**，于是「全屏遮罩」实测只有 1016×56，只盖住了顶栏那一条，点页面上任何地方都碰不到它。
2. `@keydown.esc` 挂在布局的那个 `<div>` 上。键盘事件只在焦点落在这棵子树里时才经过它，而 **macOS 的 Chrome 点按钮不给按钮焦点**（平台约定），焦点还在 `<body>` 上，事件走的是 body → document，那个 div 根本不在传播路径上。Linux / Windows 的 Chrome 会给焦点，所以这个 bug 只在 macOS 上出现。

同一个类的第三个实例：隐私说明对话框的遮罩也是个按钮，而它被后面那个 `relative` 的居中容器整个盖住了——`elementFromPoint(40, 40)` 命中的是容器，点遮罩永远关不掉。**没人报，但它一直是坏的。**

所以关闭逻辑收敛成一个 composable：`src/composables/useDismissable.js`，四条路径全部挂在 **document 的捕获阶段**：

| 路径 | 细节 |
| --- | --- |
| 面板之外的 **`pointerdown`** | 不是 `click`：从面板里按下、拖到外面松手不算「外部点击」，选文字和拖动因此不会误关（实测过） |
| **Escape** | `document` 上的 `keydown`，与焦点在哪儿无关；打开的覆盖层入栈，只有最上面那一个响应 |
| **焦点离开面板** | `focusin`；模态框用 `focusLeave: false` 关掉这一条，因为它自己有焦点陷阱 |
| **路由变化** | 菜单里点一个链接跳走，菜单不能留在屏幕上 |

外加两条硬性要求：**关掉之后焦点回到触发它的控件**（`trigger` 优先，其次是打开前的 `document.activeElement`），**`aria-expanded` 绑在同一个 ref 上**。任务必须完成才能关的路径（登录成功）走 `dismiss({ force: true })`，它跳过 `closable` 这道闸，但焦点归还照走同一条路。

全项目的覆盖层清单，以及这一轮之前它们各自的状态：

| 覆盖层 | 之前 | 现在 |
| --- | --- | --- |
| 顶栏账号菜单 | 外部点击 ❌（遮罩只有顶栏那么大）／Escape ❌（macOS）／焦点离开 ❌／路由变化 ❌ | 四条全通，焦点归还 ✅ |
| 登录对话框 | 遮罩按钮 ✅（它在 `#app-modal-root` 里，没有包含块的坑）／Escape ⚠️（挂在子树上）／自己写了一套焦点归还 | 走原语；`closable` 挂在 `canClose` 上，首次登录的对话框既不给 Escape 也不给外部点击关掉 |
| 隐私说明对话框 | 遮罩按钮 ❌（被居中容器盖住）／Escape ⚠️／自己写了一套焦点归还 | 走原语，遮罩降级成纯装饰的 `div` |
| 主题分段控件 | 不是覆盖层（一直是一组按钮），无需关闭 | 不变 |
| 导航抽屉 | 已删除（§0.2） | 不得复活 |
| Toast | 自动消失，不接受交互 | 不变 |

**禁止**：任何 `.vue` 里再出现铺满屏幕的 `<button>` 遮罩，或者任何 `@keydown.esc`——契约测试两条都盯着。

## 14. 明令禁止

- ❌ 侧边强调条（`border-l-2/4/8` 或任意 `border-l-[…]`）。被否掉过两次。
- ❌ `.vue` 里出现任何原始颜色值：hex、`rgb()`、`hsl()`、`oklch()`、`zinc-*` 这类调色板类、`bg-[#...]` 任意值语法、`bg-white` / `text-black`。**没有豁免文件**。
- ❌ 五级之外的字号、四种之外的圆角。Tailwind 的默认阶梯已被清空，写了也不生效。
- ❌ 400 / 600 之外的粗细，包括 `<b>` / `<strong>`；以及五个允许的文件之外的任何 `font-semibold`（§3.1）。
- ❌ §2.6 闭集之外的任何 `text-*` 颜色类。
- ❌ `dark:` 颜色类。
- ❌ 用 `warning` / `danger` 做大数字或大面积填充；用 `primary` 做数据色。
- ❌ 把分类色板用在到期 lane 上——一个色块只能编码一件事。
- ❌ 把不限量的包塞进任何占比图。
- ❌ 循环动画（除了骨架屏和不确定进度条）。
- ❌ 汉堡按钮与导航抽屉。
- ❌ 一页多张卡片；或给卡片内部的区域加底色、描边、圆角、阴影——它们不是卡片（§0.5）。
- ❌ 给页面卡片同时加描边和阴影：分界只有一种机制，选的是阴影。
- ❌ 给页面卡片加内边距：全宽线必须通到两边，插入量归 band。
- ❌ 在 band 上自己画 `border-t`：全宽线只有 `AppCard` 的 `divide-y` 一个来源。
- ❌ 给 `.ui-seams` 加 `gap-*`：那会把接缝抹掉。
- ❌ 让接缝网格出现空格子：底色就是分隔线色，空格子会露成一整块分隔线色的矩形。奇数个格子必须把最后一格拉满整行。
- ❌ 手写按钮、焦点环、hover 覆盖层、颜色过渡、标题行、状态徽章、进度条、账号行、分段控件、骨架块、输入框、脚注、对话框抬头——它们各自只有一个出处（§10）。
- ❌ 把类名搬进 `<script>` 或 `.js` 来绕开闭集：契约把 `src/utils/ui.js` 和 `<script setup>` 一起扫。
- ❌ 复活 `--ui-surface` / `bg-surface`：托盘色已经删掉，不是留着不用。
- ❌ 第三档控件高度（`sm:h-10`）。全项目只有 44px → 36px 一档。
- ❌ 除顶栏外的任何 `backdrop-filter`。空操作的毛玻璃不许上（§16.1）。
- ❌ 给面板写 `overscroll-behavior`——滚到头必须把滚动交还给主人。四种滚动角色见 §0.1.1，新加的滚动容器必须在契约的登记表里报到。
- ❌ 同一行的兄弟区域底边不齐；跨行那一格的天花板不等于另一列两格之和加缝（§0.6）。
- ❌ 让页面卡片在四条路由上长得不一样大（§0.5.2）；也不许把它的高度从**下限**改成上限——那会把到期分组图连刻度一起裁掉。
- ❌ 两块贴在一起的表面步进不足门槛（画布/卡片 1.08× / ΔE 3.5，卡片/凹陷 1.2× / ΔE 6），或者只在「平均值」上成立而在渐变的某一带失效（§2.1.1）。骨架块、徽章这类「画在面上的图」也算。
- ❌ 把分隔线调到 ΔE 8 以下：它是卡片内部唯一的结构性分界。
- ❌ 让侧栏和顶栏之间的步进达到 ΔE 6（那是图/底，不是同侪），或者掉到 ΔE 2.5 以下（那是一块死色）。外壳同侪的带是 2.5–5.5，两头都钉（§2.1.3）。
- ❌ 让两层外壳 veil 变成两支颜色：它们必须是同一个 rgb 三元组，只有 alpha 不同，而且顶栏是薄的那一个。
- ❌ 把顶栏的 veil 从 `background-color` 上拿走（比如让滚动上色重新占用它）。进度为 0 时它必须仍然是一块外壳面，否则屏幕最上面那 56px 又变回裸画布。
- ❌ 把画布的暖 wash 压到振幅 8/255 以下：那是侧栏唯一能采到的变化，压没了半透明就退化成 §16.1 里那个空操作。
- ❌ 把文字写在画布或顶栏上（`bg-background` 上不许出现文字颜色；顶栏那段模板里不许出现墨色类）。它们是外壳，不是文字表面（§0.1、§2.1.1）。
- ❌ 在 `.vue` 的 `<style>` 里写死字号、圆角、粗细——闭集不分「工具类」和「作用域样式」。
- ❌ 铺一个满屏的 `<button>` 当遮罩，或者把 Escape 挂在某个 DOM 子树上（`@keydown.esc`）。关闭走 §13.1 的共享原语。
- ❌ 顶栏里出现页面标题；也不许删掉那个 sr-only 的一级标题（§0.1）。

## 16. WebGL 光束背景为什么被删掉

旧版深色主题偏平，靠一层 `--blue-300` 的 WebGL 体积光束提气。新语言是浅色优先的暖调纸面：一层冷蓝光束在浅色下无处安放，在深色下也和暖色卡片打架，而暖调的深色表面本身已经有层次，不再需要这层补偿。删掉它同时消掉了「原始颜色值」规则的唯一豁免文件，规则因此变成绝对的。

## 16.1 侧栏为什么读起来像毛玻璃，却没有 backdrop-filter

需求里点名想要 frosted glass 来区分侧栏，后来又点名「你现在这样凸显不出它是一个毛玻璃的感觉」。两次都不是靠 `backdrop-filter` 解决的，理由是量出来的。

**第一次**：`SpotlightBackground.vue` 删掉以后，侧栏背后是一整块纯色画布，而模糊一块纯色等于什么都没做。浏览器实测（1280×900，`/usage`，只截侧栏那 264×900 区域，两次都加同一层半透明底，唯一变量是有没有 `backdrop-filter: blur(18px) saturate(1.4)`）：

| 指标 | 值 |
| --- | --- |
| 有差异的像素 | 158 / 237600 = **0.07%** |
| 最大通道差 | **3 / 255** |
| 差异出现的最左列 | x=12（都是图标/文字边缘的抗锯齿） |

结论没变：看不见的效果不值得一个合成层。

**第二次**：既然结论是「模糊的输入是一块死色」，那就换输入，而不是重做同一个实验。

1. 画布不再是死色：`.app-shell` 铺两道极柔的径向 wash（左上暖光、右下加深）。暖的那道的几何是为侧栏调的：这一轮从 `72% 62%` 改成 `128% 58%`——横向铺开、纵向收紧，因为侧栏那 264px 宽度上的取样点要落在渐变更靠中心的位置，wash 的振幅才不会白白浪费在横向距离上。
2. 侧栏有了自己的一层**半透明**纸色（`--ui-rail`，两个主题都是 50%），它铺在那道渐变上。

实测（1280×900，`/`，rich fixture，直接采样合成后的像素，x=258 是侧栏、卡片左边那道缝是画布）：

| 指标 | 浅色 前 → 后 | 深色 前 → 后 |
| --- | --- | --- |
| 侧栏与相邻画布的最大通道差 | 37 → **35** / 255 | 23 → **19** / 255 |
| 受影响的像素 | 整条侧栏 100% | 整条侧栏 100% |
| 侧栏自身颜色沿高度的变化 | 8 → **6** / 255 | 4 → **4** / 255 |
| 画布两端（含 wash）的变化 | 15 → **12** / 255 | 10 → **8** / 255 |
| 侧栏的 `backdrop-filter` | `none` | `none` |

第三行是关键：侧栏自己的颜色**跟着背后的渐变在变**——它确实在透，这正是 frosted 要传达的那件事；而模糊本身在侧栏这一带仍然没有可模糊的高频内容，所以仍然不加。

**这一轮的取舍要说清楚**：画布被抬亮之后，veil 与它的距离必然缩短（深色 23→19/255），侧栏自身沿高度的变化也从 8 掉到 6（浅）——因为底越高，暖 wash 能抬的振幅越小（§2.1.2）。两个数都仍然在「能看见」这一侧：6/255 和 4/255 都高于那个被否掉的 3/255，而且是**整条侧栏**的连续变化，不是抗锯齿边缘上的几百个像素。深色那一档从上一轮起就受硬约束：深色画布必须待在卡片色下面 1.20×，地板又是黑色，整条可用区间只有约 27/255。

### 16.2 顶栏的那一层：它凭什么可以有 `backdrop-filter`

顶栏是全项目唯一允许出现 `backdrop-filter` 的地方，理由必须是量出来的，规格和 §16.1 那次否决完全一样（同一个元素、同一个滚动位置、唯一的变量是模糊开还是关）。三项证据：

| 证据 | 浅色 | 深色 |
| --- | --- | --- |
| A. veil 在采样画布：顶栏自身沿长度的变化（1280×900，`backdrop-filter: blur(0px)`） | 6 / 255 | 4 / 255 |
| B. 模糊不是空操作：390×844、`scrollY=420`、只切换 `backdrop-filter` | 改动 **46.15%** 的像素，最大通道差 **16/255** | 改动 **34.67%**，最大通道差 **13/255** |
| C. 它确实在采样身后的东西：同一条顶栏，`scrollY` 0 → 420 | 改动 **53.82%**，最大通道差 **28/255** | 改动 **53.75%**，最大通道差 **18/255** |

对照：那个被否掉的 `backdrop-filter` 是 **0.07% 的像素、3/255**，而且差异全部落在图标和文字的抗锯齿边缘上。

三项证据分工明确：**A** 说的是「lg: 以上模糊是 0px，那一层纯粹是半透明」——顶栏在滚动容器外面，那里没有东西从它底下过，所以那里也不需要模糊；**B** 和 **C** 说的是「lg: 以下真的有内容从它底下过」，那里模糊才有输入。这也是为什么滚动上色写成 `background-image` 盖在 `background-color` 的 veil 之上，而不是像以前那样直接占用 `background-color`：进度为 0 时（也就是 lg: 以上永远）顶栏必须仍然是那块 veil。

**结构分区照旧**（§0.1）：侧栏 264px 宽 ＋ 一条通到底的发丝线 ＋ 一道内高光 ＋ 永远不动；顶栏共用那道内高光，接在同一条顶边上。
