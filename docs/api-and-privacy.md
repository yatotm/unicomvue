# 隐私 / Cookie / Token 说明

本说明适用于余量面板提供的账号查询服务及浏览器前端。

本说明描述本项目默认部署下的行为。接口和验证码配置由部署者管理。

## 服务说明与免责声明

- 本服务独立提供联通账号信息查询与展示，不代表运营商官方业务办理渠道，也不会变更用户的账号、套餐或业务状态。
- 手机号、短信验证码和 Token 仅用于完成账号登录与信息查询；Token 仅在用户主动操作时用于复制，不用于与本服务无关的用途。
- 本服务仅在完成用户发起的登录与查询过程中处理必要的手机号、短信验证码和 Token；服务端不会持久化保存上述凭证，浏览器端的保存范围见下文“localStorage 与 Cookie”。
- 用户应仅查询本人或已获合法授权的账号，并对提交的手机号、验证码、Token、查询授权及使用行为负责。
- 查询结果依据接口实时返回的数据整理展示；套餐权益、计费结果、业务生效状态及账号记录，以中国联通官方系统和正式账单为准。
- 用户应妥善保管账号凭证。因主动共享凭证、越权使用或违反适用规则产生的责任，由相关责任方承担。
- 为保障服务安全、稳定与公平使用，服务方可对批量请求、接口滥用、越权查询、商业化转售及其他异常使用采取访问限制。
- 使用本服务即表示用户已阅读并接受本说明。

## 数据流

1. 浏览器默认向当前站点发送登录或查询请求，由本地开发代理或 nginx 转发到部署者自己的后端。公网部署应配置 HTTPS。
2. 本项目后端默认直接请求中国联通：登录与短信使用 `https://loginxhm.10010.com`，查询使用 `https://m.client.10010.com`。除部署者自己的后端外，不存在其他中转方。显式修改 API 或上游地址会改变数据接收方。
3. 联通要求额外身份验证时，浏览器嵌入联通官方身份验证页，页面内的验证信息直接由联通处理；官方网关签发验证结果后，本项目后端继续登录请求。纯人脸验证依赖官方 App 的原生能力，当前网页会明确提示。
4. 后端在内存中保存短信、登录和验证码请求的手机号/IP 计数、短期验证结果，以及待恢复请求的加密字段、Cookie 和手机号/设备绑定；不写入数据库或文件，重启后清空。正常日志不记录手机号、登录密码、验证码、联通 Token、Cookie 值或上游原始报文。
5. 登录密码仅用于当次登录，经本项目后端加密提交至联通；不会写入应用的浏览器账号存储或服务日志。浏览器密码管理器的保存行为由用户及浏览器设置控制。

## 浏览器直接调用的接口

默认基础地址为空，即与网页同源；可通过构建变量 `VITE_API_BASE_URL` 指定自己的后端。以下接口均使用 `POST`，请求正文为 JSON 序列化数据，当前请求头为 `Content-Type: text/plain;charset=UTF-8`，响应应为 JSON。单次请求默认在 20 秒后超时，并支持在切换账号、关闭登录窗口或销毁页面时主动取消。包含凭证的请求不会自动跟随重定向。

### 登录接口

| 路径 | 用途 | 前端提交的公开字段 | 前端读取的响应 |
| --- | --- | --- | --- |
| `/gettoken/?action=send` | 请求短信验证码，必要时触发安全验证 | 手机号、浏览器登录标识、设备标识、可选的验证结果令牌 | 状态、提示信息、验证上下文 |
| `/gettoken/?action=validate` | 校验腾讯云验证码结果 | Captcha Ticket、随机串、验证上下文、手机号、浏览器登录标识、设备标识 | 状态、提示信息、后续短信请求所需的结果令牌 |
| `/gettoken/?action=login` | 使用手机号和短信验证码登录 | 手机号、短信验证码、浏览器登录标识、设备标识 | 状态、提示信息、`ecs_token`、可选的 `onlin_token` |
| `/gettoken/?action=password` | 使用联通登录密码登录 | 手机号、登录密码、设备标识，可选的官方验证结果和会话标识 | 状态、提示信息、验证要求或登录 Token |

浏览器登录标识和设备标识由前端生成并保存在当前站点的 `localStorage`，用于在登录流程中保持设备身份一致。

### 查询接口

| 路径 | 用途 | 前端提交的公开字段 | 前端读取的响应 |
| --- | --- | --- | --- |
| `/ocs_proxy/` | 查询套餐及资源余量 | `ecs_token` | 套餐名称，以及按固定白名单挑出的流量、语音、短信余量明细 |
| `/basicdata_proxy/` | 查询基础网络信息 | `ecs_token` | 脱敏号码、签约速率、LTE 状态 |
| `/qci_proxy/` | 查询 QCI、网络质量业务与已订业务清单 | `ecs_token` | 上游直接给出的 QCI（如有）、生效的 5G 网络服务质量业务（VIP / VVIP）、是否取到业务清单、限速服务状态、可用最高速率、生效业务清单 |

`/basicdata_proxy/` 返回的号码只用于在账号列表里标识当前账号，后端只放行 `1xx****xxxx` 形态的脱敏号码：上游给出完整号码时先脱敏，给出加密串或其它形态时直接留空。

查询接口接收请求正文中的 `ecs_token` 及可选的 `cookie`。短信或密码登录后会一并返回 `cookie`，由浏览器随账号保存并在查询时提交；后端将完整会话用于联通 Cookie 鉴权，不写入服务器文件。旧的手动 Token 账号仍可仅提交 `ecs_token`。

### 套餐余量明细

`/ocs_proxy/` 的上游响应里除了余量，还夹带副卡清单（`viceCardlist`，含副卡脱敏号码 `usernumber` 与加密的 `userMobile`）、计费策略编号、跳转链接等内容。后端不会整体转发这份响应，只按固定白名单逐条重建交给浏览器的对象：

| 层级 | 放行字段 | 内容 |
| --- | --- | --- |
| 顶层 | `packageName` | 套餐名称，超长会被截断 |
| 资源分组 | `type`、`userResource`、`remainResource`、`details` | 资源类型、已用与剩余合计、明细列表 |
| 余量明细 | `feePolicyName`、`addUpItemName` | 资源名称，例如“国内通用流量” |
| 余量明细 | `total`、`use`、`remain`、`usedPercent` | 总量、已用、剩余与已用占比 |
| 余量明细 | `limited`、`flowType`、`typemark`、`elemType`、`resourceType`、`realresourcetype`、`hide` | 是否无限量、流量类别、共享标记及展示用的类型标记 |
| 余量明细 | `endDate`、`endDate1`、`endXsbDate` | 有效期 |
| 余量明细 | `feePolicyId`、`addupItemCode` | 计费单元编号，仅用于在页面上区分同名资源 |

白名单之外的字段一律不出后端。**副卡数据不会以任何形式返回浏览器**：`viceCardlist` 整个数组被丢弃，其中的副卡号码（`usernumber`）、加密号码串（`userMobile`）与 `userMobileKey`、`viceCardflag` 等字段都不会离开后端。上游的跳转链接（`url`、`wTurl`、`wangTurl`）可能在查询参数里带上账号信息，页面也用不到，同样被丢弃。

后端只放行标量字段，嵌套的对象与数组不会被转发；资源分组数、每组明细条数与单个字段的长度都有上限；既没有名称也没有任何数量的明细条目会在后端被剔除。资源分组按下标对应流量、语音、短信，即使某一组没有可用内容也会保留空占位，避免浏览器错位。

### 已订业务清单

`/qci_proxy/` 的上游响应里包含账号的已订业务列表，其中还夹带手机号、姓名等身份字段。后端不会整体转发这份响应，只按固定白名单逐条挑出页面要用的三项内容交给浏览器：

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| `name` | 业务名称 | 例如“语音主服务”，超长会被截断 |
| `id` | 业务编号 | 只放行数字与字母组成的短编号，格式不符时留空 |
| `since` | 业务生效日期 | 统一整理成 `YYYY-MM-DD`，只保留日期不保留时刻 |
| `downlink_mbps` | 业务名中标注的下行峰值速率 | 仅在业务名里写明速率时出现，只取下行值 |

白名单之外的字段一律不出后端，其中手机号（`usernumber`）与姓名（`username`）不会以任何形式返回浏览器。清单条数与单条名称长度都有上限。已退订、失效、未生效、停用的业务在后端就被剔除，不进入清单，也不参与网络质量业务与限速业务的判断。

浏览器用这份清单在页面上展示“已订业务”分组列表（业务名称与生效日期），并把业务名里的下行速率作为签约速率的候选来源之一。

签约速率是联通返回的合约值，不是实时测速，也不参与 QCI 判断：签约 2000Mbps 的下行同样可能是 QCI 8，购买 5G-A 或拿到某个峰值速率都不能推出 QCI。

页面上的“签约速率”取三类来源中的最高值展示：基础网络信息接口返回的签约速率、已订业务接口返回的可用最高速率，以及已订业务名称里标注的下行峰值速率；把鼠标移到该数值上会列出全部来源及各自的数值。速率来源只影响这一处数值展示，不影响 QCI。

后端不做 QCI 推断，只把上游直接给出的 QCI 数字（如果有）、生效的 5G 网络服务质量业务（VIP / VVIP）以及“是否取到业务清单”的布尔值返回给浏览器。QCI 数字由浏览器按订购的网络质量档位推断：VVIP 记为 6，VIP 记为 8，取到业务清单但两者都未订购记为 9（3GPP 默认承载）。推断出来的值在界面上标注为“推断”，例如 `8（推断）`。上游直接给出 QCI 数字时以上游为准；完全取不到业务清单时显示“未确认”。

## 第三方前端依赖

联通要求网页身份验证时，前端仅向固定的 `https://img.client.10010.com/loginRisk/index.html` 验证页传递联通返回的原始上下文。该页面按需加载联通指定的验证码及相关资源；本项目页面只接收经过来源和窗口校验的验证结果，不采集人脸图片。

当短信接口要求安全验证时，前端按需加载：

- `GET https://turing.captcha.qcloud.com/TJCaptcha.js`

腾讯云验证码组件会在浏览器中发起完成验证所需的网络请求。组件返回的 Captcha Ticket 和随机串仅用于完成当次安全验证，并提交到 `/gettoken/?action=validate`。

## 服务端业务能力

服务端向前端提供以下业务能力：

- 手机号登录与 Token 获取
- 短信验证码发送
- 腾讯云验证码结果校验
- 套餐、流量、语音及短信资源查询
- 基础网络信息与签约速率查询
- QCI 与限速服务状态查询
- 已订业务清单查询（仅返回业务名称、业务编号与生效日期）

## 登录与查询流程

1. 用户输入手机号后，前端请求发送短信验证码。
2. 如果接口要求安全验证，前端加载腾讯云验证码；验证通过后再次请求发送短信。
3. 用户提交短信验证码，登录接口返回前端查询所需的 Token。
4. 直接输入 `ecs_token` 登录会跳过短信登录流程，首次刷新时才发送查询请求。
5. 前端先查询套餐余量，再并行查询基础速率与 QCI。
6. 自动刷新默认每 30 秒执行一次，可由用户暂停或手动触发。

查询不单独提交 `onlin_token` 字段，但会提交登录返回的 Cookie。用户点击复制后，完整 `onlin_token` 会写入系统剪贴板；长按复制则会把完整 `ecs_token` 写入系统剪贴板。

## localStorage 与 Cookie

前端可能在当前站点的 `localStorage` 中保存以下信息：

- `ecs_token` 与可选的 `onlin_token`
- 登录返回的 Cookie 会话，用于查询鉴权
- 多账号列表、当前账号标识和套餐名称
- 手机号或脱敏号码
- 最近使用的手机号
- 浏览器登录标识与设备标识
- 主题偏好

这些数据保存在当前站点的浏览器本地存储中，并受浏览器同源机制管理。请仅在可信设备上保存账号，并妥善管理浏览器扩展和设备访问权限。

前端不通过 `document.cookie` 读写 Cookie，也不依赖浏览器的第三方 Cookie。联通 Cookie 作为账号凭证交给本项目后端，由后端用于联通请求。

从账号菜单移除账号时，前端会删除该账号在本地保存的 Token；如果仍有其他账号，它们会继续保留。最近手机号、设备标识等辅助数据可能仍在 `localStorage` 中，需要彻底清除时请删除该站点的浏览器存储。

## 剪贴板与截图导出

- 用户主动复制 Token 时，完整 Token 会写入系统剪贴板。剪贴板历史、系统同步服务、浏览器扩展或其他应用可能读取或保留这份内容。
- “截图分享”在浏览器本地生成当前面板图片，图片可能包含脱敏号码、套餐、余量、签约速率、QCI 以及展开状态下的已订业务清单等页面信息。前端不会上传该截图。
- 浏览器支持图片剪贴板时，截图会写入系统剪贴板；不支持或写入失败时，前端会改为下载 PNG 文件。已下载文件会保留在用户选择的保存位置或浏览器默认下载目录中。
- 从账号菜单移除账号只会清理应用管理的本地账号状态，不会清除系统剪贴板、剪贴板历史或已经下载的截图。请在共享设备上手动清理这些副本。

## 安全建议

- 只在可信域名和可信设备上输入手机号、验证码或 Token。
- 不要在 Issue、日志、截图或文档中提交真实手机号、验证码、Captcha Ticket、`ecs_token`、`onlin_token` 或 Cookie。
- 部署站点应强制使用 HTTPS，并配置严格的内容安全策略和访问控制。
- 本项目后端默认仅接受同源浏览器请求；跨域部署需由部署者配置 `ALLOWED_ORIGINS`。静态文件本身不提供 API。
- `VITE_API_ACCESS_TOKEN` 会打包进浏览器 JS，不能作为站点密码。需要限制使用者时，应在网页和 API 之前统一设置访问控制。
- `DEBUG_RAW` 仅供部署者诊断，启用后会返回可能包含个人信息的原始响应；正常使用应关闭。
- 发现 Token 泄露时，应立即移除本地账号并通过运营商渠道使相关登录状态失效。
